# UI audit — 2026-08-26 (Phase 0 of the UI pass)

Evidence-only pass before the design brief. No source changes. Screenshots live in
`audit-2026-08/` (40 webp, light + dark, every reachable state). Reference collection
guidance for the brief is in `refs/refs.md`.

Target feel (decided): consumer nav-app (Google Maps / Waze class), map-first.
Priorities: token consistency · map HUD & playback · copy/empty/error states · motion.

## The five things that matter most

1. **No visual identity.** Stock M3 + emulator dynamic color yields a slate/indigo scheme; the
   map draws Google-blue (#1A73E8) routes, green/red pins and a purple hold marker that belong
   to no palette. Launcher is forest green (#0F3D2E). Nothing ties together.
   → Brief must pick a seed palette; map layers must derive from the theme (both modes).
2. **The playback HUD is a settings card, not a HUD.** "Driving · 0.0 / 0.6 mi · 2 min left" is
   one bodyMedium line; the speed slider and "Following" have equal weight with Pause. Nav apps
   lead with one big numeral (ETA or remaining) and demote everything else.
   → Redesign the playing/holding/waiting sheet as a proper bottom sheet with a type hierarchy.
3. **Landscape is broken.** The playback card covers the whole map (`map-playing-landscape-light`).
   Bottom overlay stack is unbounded in code (MapScreen.kt:441-539).
   → Side panel in landscape/expanded widths; `heightIn`/scroll in compact height.
4. **Card stacking has no hierarchy.** Holding banner + saved toast + stop options + route card
   pile up as 3–4 equal cards (`map-saved-confirmation-light`, `map-marker-highlight-*`).
   Transient feedback is a persistent card with OK (code uses SnackbarHost correctly on Routes).
   → One sheet + snackbars; stop options become part of the sheet, not another card.
5. **Map gestures have no accessible path** (add stop, hold, marker menu, thumbstick) and all
   copy is inline (`strings.xml` has one entry). Settings screen shows the team knows how —
   copy that pattern to the map.

## Findings by theme

### Tokens / spacing / theming
- [P2] Map/marker/chip/thumbnail colours hard-coded in 5 files (MockarrMap.kt:357-394,
  WaypointMarkers.kt:27-31, WaitChips.kt:32-33, RouteThumbnails.kt:238-241,
  SavedRoutesScreen.kt:285-286); dark basemap swaps but overlays don't.
- [P2] No static fallback scheme (<API 31 gets M3 purple); window theme light-only, no
  `values-night` → white flash on dark cold start.
- [P3] Compose side is already disciplined: ~130 `.dp` literals on an 8-pt grid (8/16/12/4/24;
  outliers 2/3/3.5/6/20), zero `.sp`, one radius (8dp). Tokens object is a small job.
- [P3] Corner radius: M3 cards (12) vs. custom 8dp vs. search field 4dp — three radii on one
  screen (`map-route-planned-light`).

### Typography & hierarchy
- [P1] HUD lacks hierarchy (see #2). Also Settings: "Updates per second: 1.0" and "Wobble
  amount: 4.5 m" are body text labels above sliders — value should read as a value.
- [P2] Saved-route titles wrap to three lines and dominate the card; meta line
  ("0.6 mi · about 2 min · Driving · Aug 26, 10:13") wraps awkwardly. Titles are geocoder
  strings ("… Middle Drive West, San Francisco") — truncate + show city as secondary.
- [P2] No top app bars: Settings uses a headline Text; Routes has no title; Setup ends with a
  bottom "Back" button (SetupScreen.kt:123).

### Map HUD & playback controls
- [P1] Idle bar "Tap the map to add stops" + disabled play + chevron: a hint living inside a
  control bar. Nav apps use an empty-state sheet or nothing.
- [P2] "Following" text button is ambiguous (state? action?). Use a toggle icon (recenter).
- [P2] Speed slider always visible at equal weight to Pause/Stop; make it a chip that expands.
- [P2] Search field stays on screen during route planning but disappears in playback along
  with the 3D toggle — inconsistent chrome rules per state.
- [P2] Bottom nav visible during playback; nav apps hide chrome while driving (revisit).
- [P3] MapLibre attribution logo is clipped behind the bottom cards in every state.
- [P3] Position/hold marker: purple dot; wait chip is amber "4:52" on a dark pill; stop pins
  are green(1)/red(2) with white ring — four unrelated colour choices on one map.
- [P3] Pulsing pin removed in round 8 — revisit under a motion budget.

### Copy, empty & error states
- [P2] Setup shows "All set — Mockarr can mock your location." beside a red ✗ item; the ✗ is
  an optional step, but the icon says failure. Use a neutral "optional" glyph.
- [P2] "Mocking isn't set up yet — routes will draw, but playback won't move your location."
  is good copy in an error-tinted banner over the idle bar — should be the idle bar's content.
- [P2] Saved toast shows the raw name with quotes and leading space (`Saved " LoopTransverse…"`)
  — the save dialog prefilled name + typed text concatenated; either a trim bug or a UX trap.
- [P3] Copy voice is otherwise consistent and good ("Recommended — keeps long playbacks alive",
  "Playback will pause here before continuing."). Keep it; externalise it.
- [P3] Empty saved routes: "No saved routes yet / Build a route on the Map tab and tap Save."
  is fine but a nav app would offer a CTA button to the Map tab.

### Motion & delight
- [P3] Only two animations in Compose (chevron rotate, a float); camera eases in MapLibre
  ignore the animator duration scale. Motion budget to be set in the brief.

### Accessibility & adaptivity (from code audit)
- [P1] Map-only interactions have no TalkBack/switch path (MapScreen.kt:144-166,
  ThumbstickOverlay.kt:85-103).
- [P2] Speed slider unlabeled (MapScreen.kt:658); status cards not live regions (570-604);
  search rows ≈44dp and results card cannot scroll, no `imePadding` anywhere (816-853).
- [P2] Overlays `fillMaxWidth` on expanded widths; landscape unbounded (see #3).
- [P3] Marker/chip text ignores fontScale; 2D/3D toggle lacks toggle semantics.

### Performance (fine)
- [P3] Marker bitmaps re-baked on selection change; `displayWaypoints` reallocated per fix;
  camera eases ignore reduce-motion. Everything else is disciplined.

## What is working — keep
Edge-to-edge and insets; predictive back; NavigationSuiteScaffold (rail on wide screens);
per-fix recomposition discipline; thumbnail caching; dark basemap style; Settings a11y pattern;
copy voice; dialog structure (wait chips, start-choice) is clear.

## Environment notes
- Old saved-route thumbnails render as route-only on flat grey in dark mode; freshly generated
  ones render the dark basemap. Cache keyed without theme → regenerate on theme change.
- Battery-optimisation step can't be satisfied on the AVD (`isIgnoringBatteryOptimizations`
  never flips); real-device check needed.
- emu.sh gaps: no `shell` passthrough; `tapon` substring matching hits attribution text and
  hint labels; tab taps drift when the IME is up.
