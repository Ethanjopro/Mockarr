# ADR 0001 — Direction change: ambition, platforms, openness, Strava baseline

Date: 2026-08-28 · Status: **provisional** (Ethan flagged these as "later down the line";
recorded now so the codebase and docs stop hard-coding the old assumptions).

## Context
Mockarr began as an Android-only, fully open, non-commercial developer tool (PLAN.md §1,
README). Ethan has raised the ambition:

1. **Platform** — Android first; an iOS port is "not out of the question".
2. **Openness / monetisation** — the open-source stance may change; light monetisation
   (ads or similar) is possible.
3. **Visual baseline** — Strava's UX/UI is the explicit reference (indigo palette, not
   orange); curated refs live in `docs/design/refs/`, the brief in `docs/design/brief.md`.
4. **Restructuring** — the codebase will be reorganised over time and must stay efficient
   and legible through it.

## Decision (provisional)
- Keep `android` as the recorded platform. Keep every `core:*` module free of Android,
  Hilt and Compose so a Kotlin Multiplatform move is a packaging change, not a rewrite.
  Be honest that iOS has **no mock-location API**: an iOS "port" is realistically a
  route-planning + simulator/dev-tool product, not a like-for-like app. That assessment is
  its own future ADR.
- Stop asserting "fully open / no tracking / F-Droid" as product truth in new work.
  Existing README/CONTRIBUTING copy stays until a real decision; PRODUCT.md, PLAN.md and
  CLAUDE.md mark the claims *under review*.
- Two commitments survive any monetisation decision: **no anti-detection features** and
  **no hidden telemetry** — anything that phones home or shows ads is disclosed in-app.
- Strava iOS is the UX/UI baseline; Material 3 remains the component system it is
  translated into (no iOS chrome).
- Structural changes from here on get an ADR before the code moves.

## Consequences
- `PRODUCT.md`, `PLAN.md`, `CLAUDE.md` updated (this session) to reflect the above.
- Add a mechanical boundary check so `core:*` cannot import `android.*`/`androidx.*`.
- New screens follow the `Screen / Sheet / Dialogs / ViewModel` file split and read colours
  only from `MaterialTheme` / `MockarrTheme`; copy goes to `strings.xml` from day one.
- Deferred: licence choice, distribution channel, ad/telemetry design, KMP assessment.
